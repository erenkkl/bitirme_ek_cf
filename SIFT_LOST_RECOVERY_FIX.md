c# SIFT Lost During Recovery - Critical Fix

**Date:** 2026-01-05
**Issue:** Drone stops completely when SIFT is lost during recovery, preventing path reacquisition
**Root Cause:** SiftPathFollower stops all movement when SIFT lost, overriding recovery commands
**Solution:** Allow recovery commands to execute even when SIFT temporarily lost

---

## 🐛 **Problem Description**

### **Observed Behavior (From User Screenshot):**
```
[AVOIDING] Seq:13 > Target:17 | AvoidRoll:18.0°
[RECOVERING] Seq:15 > Target:21 | AvoidRoll:12.9°
[RECOVERING] Seq:18 > Target:24 | AvoidRoll:0.8°
[LOST] Harita Kayip! Bekleniyor...   ← DRONE STOPS HERE
```

### **What Was Happening:**

1. ✅ Drone successfully avoided obstacle
2. ✅ Entered RECOVERING mode
3. ✅ Started turning back toward path (-8° roll command issued)
4. ❌ **SIFT lost tracking** (camera view changed too much during avoidance)
5. ❌ **SiftPathFollower detected SIFT lost → stopped all movement**
6. ❌ **Recovery commands ignored → drone hovers in place**
7. ❌ **Can't reacquire SIFT because not moving back to path**
8. ❌ **Mission failed**

---

## 🔍 **Root Cause Analysis**

### **Code Flow (BEFORE Fix):**

```csharp
HandleFlyingState() {
    if (estimatedSeq == -1 || rawSeq == -1) {
        drone.SetExternalCommand(0, 0, 0);  // ❌ STOP ALL MOVEMENT
        return;  // ❌ EXIT - Never reaches avoidance commands!
    }

    // ... SIFT calculations ...

    // ⚠️ This code is NEVER REACHED when SIFT lost!
    if (avoidanceActive && avoidanceMode == RECOVERING) {
        recovery_roll = -8.0°  // Never applied!
    }
}
```

**The problem:** Recovery commands are generated by `obstacle_avoidance_node.py` but **never applied** because SiftPathFollower exits early when SIFT is lost.

---

## ✅ **Solution Implemented**

### **1. Allow Recovery Commands During SIFT Loss**

**File:** `SiftPathFollower.cs` lines 185-211

**BEFORE:**
```csharp
if (estimatedSeq == -1 || rawSeq == -1) {
    drone.SetExternalCommand(0, 0, 0);  // Stop everything
    return;  // Exit
}
```

**AFTER:**
```csharp
if (estimatedSeq == -1 || rawSeq == -1) {
    // NEW: If in RECOVERING mode, continue executing recovery commands
    if (enableAvoidance && avoidanceActive && avoidanceMode == 2) {
        // Don't return - continue to apply recovery commands
        Debug.LogWarning("[LOST+RECOVERING] SIFT lost but continuing recovery...");
    }
    else {
        // Not in recovery - safe to stop
        drone.SetExternalCommand(0, 0, 0);
        return;
    }
}
```

---

### **2. Provide Basic Movement During Blind Recovery**

**File:** `SiftPathFollower.cs` lines 247-322

**New Logic:**
```csharp
bool siftLost = (estimatedSeq == -1 || rawSeq == -1);

if (siftLost && avoidanceActive && avoidanceMode == RECOVERING) {
    // SIFT lost during recovery - use simple forward motion
    pitchCmd = forwardSpeed * 0.8;  // Keep moving forward
    rollCmd = 0;  // Will be set by avoidance blend (recovery roll)
    yawCmd = 0;  // Maintain current heading

    stateTag = "RECOVERING-BLIND";  // Special state for logging
}
else if (!siftLost) {
    // Normal SIFT-based navigation
    // ... existing SIFT calculations ...
}

// Recovery roll (-8°) applied here regardless of SIFT status
if (avoidanceActive && avoidanceMode == RECOVERING) {
    rollCmd = currentAvoidanceRoll;  // ✅ NOW APPLIED!
}
```

## 🔧 **How It Works**

### **State Machine During SIFT Loss:**

```
NORMAL (SIFT tracking)
  ↓
AVOIDING (SIFT may degrade but usually maintained)
  ↓
RECOVERING + SIFT LOST
  ├─ [Unity] Enters "RECOVERING-BLIND" mode
  ├─ [Unity] Applies basic forward motion (12 m/s)
  ├─ [Unity] Applies recovery roll from ROS2 (-8°)
  ├─ [ROS2] Continues sending recovery commands
  └─ [Result] Drone flies back toward path
  ↓
SIFT REACQUIRED (camera sees path again)
  ↓
RECOVERING (normal SIFT-guided recovery)
  ↓
NORMAL
```

## ⚠️ **Safety Considerations**

### **Why This Is Safe:**

1. **Only active during RECOVERING mode** - not during normal SIFT-lost scenarios
2. **Limited duration** - MIN_RECOVERY_DURATION = 2 seconds max
3. **Low speed** - Uses avoidanceSpeedMultiplier (0.8 = 80% speed)
4. **No obstacles ahead** - Only enters recovery when obstacle cleared
5. **Falls back to stop** - If recovery fails, obstacle_avoidance_node will timeout

### **Fallback Protection:**

If SIFT not reacquired within recovery duration:
```python
# In obstacle_avoidance_node.py
if time_in_recovery > MIN_RECOVERY_DURATION and sift_confidence < 0.3:
    # Recovery failed - return to AVOIDING or EMERGENCY_STOP
```
